# 복지로 프로그램 개선 목록 (Ver10.07 기준)

정책뉴스 때와 같은 방식: 사용자와 대화하며 모으고, 사용자가 요청하면 한 번에 코드에 반영한다. 반영 전까지 코드는 건드리지 않는다.

현재 탭: ① 중앙부처복지서비스 · ② 지자체복지서비스 · ③ 리스트업 · ④ 포스팅 관리 · ⑤ 블로그 스크랩 · ⑥ 인포그래픽 작업 · ⑦ 키워드 등록 · ⑧ 포스팅 이력관리 · ⑨ 설정

## 1. 정책뉴스(Ver10.09~10.10)에서 고친 것 중 같은 컨셉 적용 (2026-10-14 요청)

정책뉴스 수정 항목을 복지로 코드와 하나씩 대조했다.

**적용할 것**
- **"🔍 통합"(네이버 통합검색) → "📋 제목 복사"** (④ 포스팅 관리 탭)
  - 제목 후보 4줄 각각의 "🔍 통합" → "📋 제목 복사"(그 후보 제목 복사)
  - 직접 입력 줄의 "🔍 통합" → "📋 제목 복사"(입력칸 제목 복사)
  - 아래 버튼 줄 "🔍 제목 통합검색" → "📋 제목 복사"(선택 항목의 최종각색 제목 복사)
  - 통합검색을 여는 코드 분기는 지운다. 🔍 블로그·앞구·뒷구·🔍 제목 블로그검색은 그대로. 버튼 폭은 정책뉴스처럼 줄 폭이 넓어지지 않게 맞추고 가상 화면에서 전후 폭을 잰다.
- **탭 이름 "⑥ 인포그래픽 작업" → "⑥ 인포그래픽 작성"** — 정책뉴스 "4)인포그래픽 작성"과 같은 이름. 코드 안 안내 문구·주석의 "인포그래픽 작업"(약 10곳)도 같이 바꾼다(변경 이력은 그대로).
- **코드 카드 "③ 퍼플렉시티 그림 선택…" → "③ 퍼플렉시티/GPT 그림 선택…"** (아래 대기 항목을 여기로 옮김)

**해당 없음(복지로에 같은 기능이 없거나 이미 그렇게 되어 있음)**
- 다중뉴스 사전검토 탭·프롬프트0 — 복지로에 없음(Gemini 사전스크리닝은 Ver10.06에서 이미 삭제)
- 워터마크처리 탭·Pillow — 복지로에 없음
- 탭 이동을 번호 대신 탭 화면으로 — 복지로는 이미 탭 화면으로 이동한다(`notebook.select(self.settings_tab)`)
- 탭 번호 통일 — 복지로 탭은 ①~⑨로 이미 순서대로다
- 키워드 등록 "중복의심 글 포스팅 허용"(정책 Ver10.07) — 복지로 ⑦ 키워드 등록에는 중복의심 격리 기능 자체가 없다

- **"🌐 검색 키워드로 네이버 열기" 버튼 삭제** (④ 포스팅 관리 탭 키워드 리서치 줄, `_open_naver_with_research_keyword`) — 사용자 답(2026-10-14): 삭제해도 됨. 이 버튼만 쓰는 코드도 같이 지운다(다른 곳이 쓰는 `open_naver_search_in_chrome`은 확인 후 판단).

## 3. ④ 포스팅 관리 탭 — 작업 순서대로 칸 나누기 (2026-10-14 요청, 결정은 추천안대로)

문제: 실행 순서와 화면 순서가 다름(제목 후보 확정이 ⑦⑧ 아래), "작업 순서" 칸에 버튼 13개가 몰림, 키워드 리서치 줄이 넓어 "🔍 검색량·자동완성 조회"가 1600px 화면에서도 오른쪽 밖으로 잘림, "기타 관리"에 성격 다른 버튼이 섞임.

**배치(위 → 아래)** — 기능은 그대로, 배치·문구만 바꾼다
- 서비스 목록(그대로)
- **STEP 1 — 키워드 리서치**(가치판단 앞; AI가 재조사를 요청하면 다시 여기로): [📋 재조사 요청 키워드 채우기] 검색 키워드 [✖] / [🔍 키워드 리서치 실행] [🔍 검색량·자동완성 조회] [📋 AI에게 결과 전달] — 두 줄로 나눠 잘리지 않게, 정책뉴스식 ①②③ 안내 + 결과 상태 줄. "📋 키워드 복사"는 남김, "🌐 네이버 열기"는 삭제(1번).
- **STEP 2 — 가치판단(Claude)**: [프롬프트+자료 복사] [프롬프트만 복사] → [가치판단 결과 저장] + 4번 경쟁 블로그 입력칸
- **STEP 3 — 제목 후보 확정**: 지금 칸을 그대로 이 자리로(🔍 통합 → 📋 제목 복사는 1번)
- **STEP 4 — 초안 작성**: [프롬프트+자료 복사] [프롬프트만 복사] → [초안 결과 저장]
- **STEP 5 — 최종각색**: [프롬프트+자료 복사] [프롬프트만 복사] → [최종각색 결과 저장(.md)]
- **STEP 6 — 완료 처리**: 상태 선택 + [적용]
- 기타: 폴더 열기 3개 / 연관 정책 / 새로고침 / 엑셀 저장(🔍 제목 블로그검색은 STEP 3 근처로, 제목 통합검색은 1번대로 📋 제목 복사)

**정한 것(사용자: 추천안대로)**
- 키워드 리서치는 STEP 1(가치판단 앞) — 복지로 프롬프트는 복사할 때 리서치 결과를 같이 넣는다.
- ⑦ 인포그래픽 복사 버튼 2개는 ⑥ 인포그래픽 작성 탭으로 옮긴다(정책뉴스처럼 인포그래픽은 그 탭에서).
- 버튼의 동그라미 번호(⓪①②…)는 뺀다 — STEP 번호와 겹침. 메시지·안내 안의 "② 가치판단 결과 저장" 같은 표현도 새 버튼 이름에 맞춘다. 상태 값(🔎 가치판단대기 등)은 저장 데이터라 그대로.
- **재조사 요청 키워드 채우기 개선**: 지금은 AI 답변을 가치판단 결과로 먼저 저장해야만 채워짐 → 클립보드에 AI 답변이 있으면 거기서 바로 채우고, 없을 때만 저장된 결과에서 찾는다.
- 칸 사이 "다음: STEP n" 안내.

## 4. STEP 2에 "경쟁 블로그 글" 입력칸 (2026-10-14 요청, 결정은 추천안대로)

- [📂 스크랩 폴더에서 불러오기]: 스크랩 폴더의 .md를 골라(기본 전부) 칸에 채움. 직접 붙여넣기·편집 가능. [지우기].
