# 중복 체크 개편 컨셉 (2026-10-16, 사용자와 합의 — 코드 아직 안 고침)

대상: 정책뉴스·복지로 관리 프로그램. 포스팅 엔진은 건드리지 않는다.

## 목적 (사용자)
- 지금 방식(핵심DB 요약본 + 가중치 점수)은 정확도가 낮아 중복을 막지 못한다 → **MD를 통째로 보관하고 본문 전체로 비교**한다.
- 원문·정책 중복보다 **"내가 과거에 포스팅했는가"**가 중요하다 → 정책뉴스·복지로를 넘나들며 비교.
- 가능하면 초기에 발견(다 만들고 지우는 일 방지), 아니면 2중 체크.
- 기존 글의 업데이트성이면 새로 쓰지 않고 기존 글을 열어 수정한다.

## 지금 코드에서 확인한 것
- 정책뉴스 키워드 등록이 `extract_core(md, keyword="")`로 넘겨 핵심DB에 핵심키워드 = 제목 전체, 분산키워드 = 빈 값으로 쌓인다(이력에는 3)탭 키워드가 있는데 안 씀). 개편 때 같이 고친다.
- 복지로는 servId·이름 유사·같은 제목만 확인 — 본문 비교 없음. 두 프로그램 사이 교차 확인 없음.

## 샘플 5개 비교 결과 (2026-10-16, 사용자 제공 복지로 MD, 로컬 계산)
- 같은 정책 다른 각도(버팀목 기본 ↔ 연장·추가대출): 글자 4묶음 겹침 0.13, 단어(TF-IDF) 0.16, 비슷한 문장 3/64
- 제목 키워드는 같지만 다른 상품(주거안정 월세 HF보증 ↔ 기금 대출): 0.03 / 0.05 / 0 — 본문 비교로 갈림
- 관계없는 글: 0.02~0.05
- → 본문 % 하나로는 "다른 각도"와 "재탕"을 못 가른다. 같은 내용을 두 번 쓴 실제 예는 아직 없다(사용자) — 기준값은 처음엔 정하지 않고 겹친 내용을 보여 준 뒤 사람이 고른다.

## 판정 (3단계)
1. 주제 같음? — 제목 메인 키워드·정책명·해시태그로 과거 글 후보(빠름, 초기 체크용)
2. 본문 겹침 — 후보와 소제목 단위 비교, 겹친 소제목·문장 표시(단어 TF-IDF + 글자 묶음, API 없음, 색인 미리 계산)
3. 같은 주제+많이 겹침 → 업데이트 권장 / 같은 주제+적게 겹침 → 다른 각도 새 글(겹친 소제목 표시, 내부링크 후보) / 다른 주제 → 통과

## 체크 시점
| | 정책뉴스 | 복지로 | 재료 |
|---|---|---|---|
| 초기 | 0 후보선별·A 전 | STEP 1 빠른 판정 | 뉴스 제목·원문 / 정책명·요약 |
| 저장 전 | 3)탭 최종각색 저장 | STEP 4 최종각색 저장 | 완성 본문 |
| 등록 | 키워드 등록 | 키워드 등록 | 완성 본문 + 보관소에 넣기 |

## 보관소
- 복지로: 키워드 등록 때 `final_posts_backup/{제목}/`에 이미 모은다 — 이것을 보관소로 쓴다.
- 정책뉴스: 지금은 날짜별 폴더에 폴더 없이 모이고 키워드 등록에 쓴다 → **복지로처럼 글마다 폴더**로 보관.
- 두 프로그램은 서로의 보관소를 읽는다(설정 탭에 상대 경로 칸). 색인 파일에 시리즈·제목·핵심 키워드·날짜·URL(포스팅 이력 엑셀에서 제목으로 찾아 채움).
- 메인 포스팅 프로그램 `Naver_blog_keyword_markdown_backup`은 중복 체크에 안 쓴다(엔진 안 기능이라 그대로 둠 — 포스팅 후 원본 삭제 대비 안전장치).
- 이미 올린 글 중 보관 안 된 것은 블로그에서 내려받아 넣는다 — **별도 작업(사용자)**.

## 업데이트 흐름 (사용자 결정)
- 기준(제안): 사실이 바뀜(금리·한도·기간·신청일) → 기존 글 업데이트 / 사실은 같고 새 질문 → 다른 각도 새 글 + 기존 글 내부링크.
- 네이버 반영은 **사용자가 직접 수정**한다(엔진은 새 글 발행만 함).
- 제목은 최소 수정, 본문에 업데이트 이력 표기.
- 결과물: (a) 수정 MD 전체 (b) 수정 목록 — 소제목·기존 문구(Ctrl+F로 찾게 그대로)·새 문구 (c) 업데이트 이력 한 줄(도입부 아래).
- 저장 때 팝업으로 (b)(c) + 글 주소 열기, 해당 글 보관 폴더에 `업데이트_날짜` 파일로 따로 보관.
- 업데이트 프롬프트 새로 필요(정책뉴스·복지로 각각).
