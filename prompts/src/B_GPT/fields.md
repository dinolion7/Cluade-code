# B·GPT 주제 필드 설명

주제 파일(`topics/{주제}.md`)은 `@@ 필드명` 줄 아래에 값을 적는다. `?`가 붙은 필드는 없어도 된다.
"줄 안" 필드는 한 줄 값, "블록" 필드는 여러 줄 값이다. `_`로 시작하는 필드(예: `_메모`)는 기록용이다.
원본의 "스타일 A와 다르게", "GPT 스타일 A보다 ~" 같은 비교 문구는 옮기지 않는다(공통 본문이 자기완결형 기준으로 대신한다).

| 필드 | 형태 | 내용 |
|---|---|---|
| 역할 | 블록 | [역할]의 화자 설명 문단 (어떤 분야 질문에 편하게 답해주는 정보 전달자인지, 커뮤니티 대화 톤) |
| 역할규칙 | 블록 | [역할] 아래 이 분야 불릿 (글의 범위, 다루지 않는 것, 광고·판촉 말투 금지, 이 분야 조장 금지 등). 공통인 판결문·공포·가짜 수치·새 명칭 생성은 넣지 않는다 |
| ?다루는범위 | 블록 | `[다루는 범위 — 반드시 준수]` 머리줄을 포함한 섹션 전체 |
| 고유명사 | 줄 안 | 원형을 살릴 고유명사 종류 (예: 세목명·공제명·기관명) |
| 초안문서어 | 줄 안 | 초안에 흔한 문서어 예 3~4개 |
| 문서어 | 블록 | 불릿 3개: "- A→B, C→D 처럼 바꾼다", "- 실제로 검색되는 …(…)은 원형 그대로 둔다", "- …와 조항 번호는 제목에 넣지 않는다" |
| 정보항목 | 줄 안 | 보존할 정보 종류 |
| 고유명사대조 | 줄 안 | 대조 목록에 넣을 이름 종류와 예 (예: 공제명(예: 국세청, 홈택스, 근로장려금, 연말정산 간소화서비스, 세무서 등)) |
| 사례예 | 줄 안 | 익명 사례 묘사 예 2개 (따옴표 없이, 예: 프리랜서로 일하다가 처음 종합소득세 신고하는 사람이", "부모님께 전세보증금을 지원받은 사람이) — 바깥 따옴표는 공통 본문이 붙인다 |
| 재배열실패전 | 줄 안 | 표면 재배열 실패 사례의 원래 문장 |
| 재배열실패후 | 줄 안 | 어순만 바꾼 문장 |
| 제목명사범위 | 줄 안 | 이 분야의 구체적 명사 범위 |
| 결합금지예 | 줄 안 | "이미 두 조건을 담은 항목" 예시 문장 1개 |
| ?제목금지추가 | 블록 | 이 분야의 제목 추가 금지 불릿 |
| 제목예시 | 블록 | "좋은 예: …" 2~3줄 + "나쁜 예: … (이유)" 3~4줄 |
| 결과단정예외 | 줄 안 | 도입부에서 결과를 단정하지 말아야 할 사안 예 (예: 가산세 부과 여부·공제 인정 여부·환급액처럼 소득·지출 구조나 국세청 심사에 따라) |
| 도입예시 | 줄 안 | 도입부 형식 예시 한 단락 (따옴표 없이) |
| 소제목명사실패 | 줄 안 | 명사로 끝나 실패한 서술형 소제목 예 |
| 소제목명사성공 | 줄 안 | 완결된 문장으로 고친 예 |
| 소제목질문예 | 줄 안 | 질문형 소제목 예 2~3개, " / " 구분 |
| 소제목서술예 | 줄 안 | 서술형 소제목 예 2~3개, " / " 구분 |
| 맺음말예 | 블록 | 맺음말 예 1~2개 ("  예: \"…\"") |
| ?마무리금지추가 | 블록 | 이 분야의 마무리 추가 금지 불릿 |
| 안전규칙 | 블록 | `[… 안전 규칙]` 머리줄을 포함한 섹션 전체 (두괄식 도입부에서도 단정하지 않는다는 문장 포함) |
| ?추가규칙 | 블록 | 이 분야에만 있는 그 밖의 섹션 전체 (머리줄 포함) |
| 분량항목 | 줄 안 | 분량을 위해 만들면 안 되는 것 |
| 해시태그예 | 줄 안 | 예: #연말정산 #종합소득세 |
| 점검정보 | 줄 안 | 점검 7번의 보존 정보 목록 |
| 점검안전 | 줄 안 | 점검 8번: 이 분야 단정·조장 표현 확인 한 문장 |
| ?점검추가 | 블록 | 이 분야 추가 점검 항목 ("12. …"부터) |
