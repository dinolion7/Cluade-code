# 지식인 파이프라인 (2차 각색 앞단계)

네이버 지식인 질문 한 건이 블로그 글이 되기까지의 단계다. 2차 최종각색은 `prompts/dist/`(원본은 `prompts/src/`)에 있고, 이 폴더에는 그 앞단계 프롬프트를 둔다.

| 순서 | 파일 | 모델 | 하는 일 | 다음 단계로 넘기는 것 |
|---|---|---|---|---|
| 1 | `1_사전판단_경제금융.md` | Claude(웹 검색) | 포스팅 가치 판정, 인접 질문 확장, 키워드 경쟁 확인, Perplexity 리서치 지시문 작성 | 리서치 지시문 |
| 2 | `2_퍼플렉시티_조사_{경제·IT·교육·건강·자동차}.md` | Perplexity | 공식 자료 중심 사실 조사 | 조사 결과 원문 |
| 3 | `3_검증_{경제금융·경제복지연금·경제고용노동·경제법률행정·경제부동산}.md` | Claude(웹 검색) | 1·2차 검색으로 대조, 틀린 값 교정, 확인 안 되는 내용 삭제, **포스팅 가능 판정(유지/폐기)** | 검증된 자료(유지일 때만) |
| 4 | `4_1차각색_Claude.md` / `4_1차각색_GPT.md` | Claude 또는 GPT | Perplexity 고유의 구조·문체를 부숴 형태를 비튼다(정보는 유지) | 1차 초안 |
| 5 | `prompts/dist/{A·B}_{주제}_{모델}.txt` | Claude 또는 GPT | SEO·AEO 최종 각색 | 블로그 원고 |

건강 주제는 5단계 뒤에 검수·편집 단계가 더 있다(`prompts/USAGE.md` 2장).

- 1차 각색(4)은 주제 공용이며 모델별 2개(Claude·GPT)뿐이다.
- 사전판단(1)·Perplexity 조사(2)·검증(3)은 주제별로 따로 있다. 검증은 Claude에서만 돌린다.
- 검증 5개는 분야 이름·우선순위 출처 줄만 다르고 나머지는 같다. 규칙을 고칠 때는 `3_검증_경제금융.md`를 고친 뒤 나머지에 같은 내용을 옮긴다.
- 아직 받지 않은 것: 사전판단의 경제금융 외 버전, 검증의 세금·IT·교육·건강·자동차 버전(있다면).

## 단계별 원칙

- **Perplexity(2)는 사실 조사만 맡는다.** 조사 내용에는 손대지 않고, 결과를 적는 방식만 다음 단계에 맞췄다: 확인 못 한 항목은 문장 대신 `[확인불가: 항목]` 태그, 공식 자료끼리 다르면 `[자료 불일치: 항목 — 기관A / 기관B]` 태그, 날짜는 연도 있는 절대 표기, 수치 옆에 출처 기관명, 질문자의 물음마다 답하거나 태그 표시. 태그는 검증(3)이 모두 정리하므로 각색 단계로 넘어가지 않는다.
- **사실 교정은 검증(3)이 맡는다.** 확인되지 않거나 1·2차 검색 결과가 갈려 판단이 애매한 내용은 고쳐 쓰지 않고 **삭제**한다. "확인되지 않습니다", "공식 사이트 확인 필수" 같은 문장이 독자에게 가면 이탈과 신뢰 저하로 이어지기 때문이다.
- **덜어낸 뒤 글이 안 되면 폐기한다.** 검증(3) 출력 맨 위의 `## 포스팅 판정: 폐기`가 그 표시다. 폐기면 검증된 자료를 아예 출력하지 않으므로 다음 단계로 넘어갈 수 없다. 관리 프로그램은 이 줄로 자동 분류할 수 있다.
  - 폐기 조건: 핵심 물음에 확인된 답이 없음 / 확인된 정보 갈래 2개 미만 / 일반론만 남음 / 핵심 수치·조건의 절반 이상이 확인 불가
- **1차(4)는 형태 비틀기 전용이다.** Perplexity 결과를 바로 2차에 넣으면 모든 글이 같은 골격이 되므로, 1차에서 구조·문체를 먼저 부순다.
- **2차(5)는 검색 노출을 맡는다.** 키워드를 본문에서 뽑아 메인(1차)·서브(2차)·롱테일(3차)로 나누고, 이 구분을 제목·도입부·소제목·해시태그에 그대로 잇는다.

## 2차 제목 규칙 요약

- 구조: `[메인 + 서브], [롱테일 + 종결]` — 메인은 반드시 맨 앞, 쉼표는 정확히 1개, 쉼표 앞 30자 이내
- 길이: 공백 포함 35~55자 기본, **60자 절대 상한**(넘으면 검색 결과에서 잘린다). 넘으면 뒤(롱테일·종결)부터 줄이고 메인·서브는 건드리지 않는다
- 롱테일은 한 축 안에서 표현 2~3개까지(예: "서류평가와 면접"). 다른 축은 소제목으로
- 숫자는 핵심 1개, 천 단위 쉼표 금지("1200만 원")
- 제목의 키워드·물음은 모두 본문에 있어야 하고, 본문이 답할 수 있는 물음만 쓴다
- 예: `특수교육과 학생부종합전형, 일반 교육 중심 학생부로 지원하면 서류평가와 면접에서 불리하게 읽힐까?` (54자)

결과물 한 편을 형식 점검하려면(무료, API 없음):

```
python3 tools/rulecheck.py <결과 파일> <A_Claude|B_Claude|A_GPT|B_GPT>
```

제목 60자·쉼표 1개·천 단위 쉼표·소제목 특수문자·해시태그 기호·확인 실패 문장("확인되지 않" 등)을 함께 본다.

## 변경 이력 (2026-10-05)

- 3 검증: 확인 불가 항목을 "원문 유지"에서 "삭제"로 바꿈. 애매한 항목도 확인 불가로 처리. 조사 실패 보고 문장·태그 삭제. [6단계] 포스팅 가능 판정(유지/폐기) 신설
- 4 1차(공통): 확인 실패 문장은 반영하지 않고 항목째 뺌, 같은 사실의 중복은 한 곳에 합치기 허용, 분량 하한(1,500자 등) 폐지 → 정보량 기준
- 4 1차(Claude): 인용 마커([4][7] 등) 제거 규칙 추가, "왜 이런 규정이 생겼는지" 배경 서술 지시를 "원문에 있는 범위"로 한정
- 4 1차(GPT): 고유 대상 뭉뚱그림 금지·없는 인과관계 금지 추가(Claude판과 맞춤), 코드블럭 여러 개 분할 허용 삭제
- 1 사전판단: 변경 없음
- 2 Perplexity(5개 주제): 확인불가·자료 불일치 태그, 절대 날짜("현재/올해/최근" 대체 규칙 삭제), 출처 기관명 문장 안에 표기, 물음별 답, 근거 없는 빈도 표현("~인 경우가 많습니다") 권장 삭제
- 3 검증: 분야별 4개 추가(복지연금·고용노동·법률행정·부동산), 태그 항목을 반드시 검증하고 검증된 자료에는 태그를 남기지 않음
